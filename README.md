# 慾望清單・冷靜期（DMS）v0.2

衝動購物克星：依金額自動鎖定「確定購買」，冷靜期過後才能決定買或不買。
單一檔案 `index.html`，不需建置，直接放上 GitHub Pages 即可使用。

## 部署到 GitHub Pages

1. 在 GitHub 建立新的 repository（例如 `desire-list`）。
2. 上傳 `index.html`（和這份 README）到 repository 根目錄。
3. 進入 **Settings → Pages**，Source 選 **Deploy from a branch**，Branch 選 `main` / `/ (root)`，按 Save。
4. 約 1 分鐘後即可從 `https://<你的帳號>.github.io/desire-list/` 開啟。
5. 第一次開啟時設定主密碼。

> 本機測試：直接用 Chrome / Edge 打開 `index.html` 即可。若瀏覽器顯示「不支援加密」，改用
> `python3 -m http.server` 再開 `http://localhost:8000`。

## 跨裝置同步（v0.2 新增）

GitHub Pages 沒有後端，所以資料原本只存在各自的瀏覽器裡，換裝置就看不到。現在會把同一份**加密後**的資料
存到你自己 GitHub 帳號的私人 Gist，所有裝置用同一組主密碼讀寫。

**第一台裝置（資料所在的電腦）**
1. 開網站 → 解鎖 → 「設定 → 跨裝置同步」。
2. 點「建立 GitHub 權杖」，只勾 **gist**，Expiration 建議選 No expiration，產生後複製 `ghp_…`。
3. 貼上權杖，按「開始同步」。畫面會出現 QR Code 和登入連結。

**手機／其他裝置**
- 用相機掃 QR Code（或打開傳過去的登入連結），輸入**電腦的主密碼**，按「連結並進入」。
- 如果手機上已經有資料：解鎖後會跳出「連結既有同步」，可以勾選把手機的品項合併進去，名稱和金額都相同的會自動略過。
- 之後隨時可以在「設定 → 跨裝置同步 → 在新裝置登入」叫出 QR Code。

**同步怎麼運作**
- 每次修改約 2 秒後自動上傳；切回網頁、恢復連線時，以及每分鐘，都會自動抓取其他裝置的修改。
- 右上角狀態：`只存在本機`／`同步中…`／`已同步`／`離線・已存本機`／`同步失敗`，點一下就會立即同步。
- 兩台裝置同時改不同品項會各自保留；改到同一個品項，以最後修改的為準；在一台刪掉，另一台也會刪掉。
- Gist 裡只有 AES-256-GCM 密文，GitHub 和任何人沒有主密碼都看不到內容，權杖也不會上傳。
- 在一台裝置變更主密碼後，其他裝置會出現「請重新輸入主密碼」，輸入新密碼就好。舊的 QR Code 會失效，要重新產生。

## 與規格書的差異（刻意的初版取捨）

- **技術棧**：規格書寫 React / Next.js + Zustand + RxJS。初版改用單一 HTML + 原生 JavaScript，
  目的是本週可上線、零建置、GitHub Pages 直接部署。功能面一致，之後要遷移到 Next.js 時資料格式可沿用。
- **儲存**：密文同時寫入 IndexedDB 與 localStorage（互為備援），規格書是依資料量分流。
- **同步**：規格書只規劃瀏覽器本機儲存，沒辦法跨裝置。v0.2 加上 GitHub Gist 加密同步，仍然不需要自架後端。

## 注意事項

- 沒開同步的話，資料只存在「這個瀏覽器」。開了同步，雲端上就有一份加密副本。
- 主密碼無法找回；忘記的話，所有裝置和雲端資料都解不開。
- GitHub 權杖等於可以讀寫你的 Gist，不要分享；不用時可以到 GitHub → Settings → Developer settings → Tokens 撤銷。
- 前端門禁保護的是「資料內容」，網頁程式碼本身在公開 repo 中是看得到的，這是靜態託管的正常情況。
